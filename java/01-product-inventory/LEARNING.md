# 상품·재고 실습 회고

## 리팩터링한 이유

`main` 메서드가 점점 무겁고 복잡해지면서 단위 테스트를 작성하기 어려웠다. 코드를 읽기 힘든 부분도 많아 역할을 나누는 방향으로 리팩터링했다. 메서드 이름만 보고도 어떤 기능을 하는지 알 수 있도록 이름을 정리하는 데 신경 썼다.

## DTO를 따로 만들지 않은 이유

`findAll()`에서는 별도의 DTO를 만들지 않고 `Product` 객체를 반환하도록 했다. 현재 코드에서 DTO를 추가하고 변환하는 작업은 복잡도를 더 높일 것이라고 판단했다. 이번 구현에서는 구조를 단순하게 유지하는 쪽을 선택했다.

## AI 코드 리뷰로 알게 된 Scanner 문제

`static Scanner`의 문제는 예상하지 못했다. 혼자서는 생각하지 못했을 부분이었지만 AI 코드 리뷰를 통해 알게 되었다. 문제의 원인과 어떤 방식으로 해결할 수 있는지도 함께 알게 되었다.

## 기술 메모

아래는 회고와 구분한 현재 코드 기준의 기술 보충이다.

- `findAll()`은 `List.copyOf(products)`를 반환하므로 반환된 목록에 상품을 추가하거나 삭제할 수 없다. 다만 목록 안의 `Product` 참조는 공유되므로 상품의 상태까지 읽기 전용이거나 불변인 것은 아니다.
- `static Scanner`는 같은 JVM에서 `System.in`을 교체한 뒤 다시 실행해도 처음 입력원에 연결된 상태로 남는 문제가 있었다. 현재는 `private final Scanner` 인스턴스 필드를 생성자에서 초기화해, 새 인스턴스가 생성될 때의 입력원을 사용하도록 했다.
