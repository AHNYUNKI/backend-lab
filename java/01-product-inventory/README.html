01. 상품 등록·목록 조회·재고 변경

순수 Java로 상품을 메모리에 보관하는 프로그램을 직접 만듭니다. 오늘의 중심은 객체 설계, 컬렉션, 테스트, 디버깅입니다. Spring, 데이터베이스, 로그인, 복잡한 콘솔 메뉴는 다음 단계로 남겨둡니다.

준비된 것

  • Main.java: 실행 확인 문구와 작업 시작 위치
  • MainTest.java: 시작 코드가 예외 없이 실행되는지 확인하는 테스트 1개
  • ProductInventoryTest.java: 직접 채울 테스트 4개. 현재는 @Disabled 상태
  • pom.xml: Java 21, JUnit 5, 컴파일·테스트 설정

상품 클래스, 저장용 컬렉션, 등록·조회·변경 로직은 직접 작성합니다. 완성 코드나 메서드 시그니처는 미리 정하지 않았습니다.

실행과 테스트

이 README가 있는 java/01-product-inventory 폴더에서 실행합니다.

bash
mvn test
mvn compile
java -cp target/classes dev.backendlab.inventory.Main

예상 출력:

text
상품·재고 실습 준비 완료. README.md의 과제를 시작하세요.

현재 Mac에서는 기존 Maven 캐시를 사용해 mvn -o test로도 검증할 수 있습니다. -o는 오프라인 모드이므로 다른 환경에 필요한 의존성이 없다면 일반 mvn test를 사용합니다. Maven Wrapper는 추가하지 않았으며 설치된 mvn을 사용합니다.

IntelliJ

  1. Open에서 backend-lab/java/01-product-inventory 폴더를 선택합니다.
  2. pom.xml을 Maven 프로젝트로 불러옵니다. 자동 인식되지 않으면 해당 파일의 Add as Maven Project를 사용합니다.
  3. Project Structure → Project SDK를 JDK 21로 설정합니다.
  4. Settings → Build, Execution, Deployment → Build Tools → Maven → Runner → JRE도 Project SDK로 맞춥니다.
  5. Main.main() 옆 실행 버튼으로 실행하고, 테스트 클래스 옆 버튼으로 테스트합니다.

현재 Mac의 ARM용 JDK 21 위치는 다음과 같습니다. SDK 목록에 없다면 이 폴더를 추가합니다.

text
/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home

Maven 창을 사용하는 경우 Maven home path는 설치된 /opt/homebrew/opt/maven/libexec를 선택할 수 있습니다. 저장소 루트는 전체 자료를 보는 용도이며, 오늘의 실행 프로젝트는 이 폴더입니다.

요구사항

기능 완료 기준
상품 등록 ID, 이름, 가격(정수 원), 재고 수량을 가진 상품을 등록할 수 있습니다.
목록 조회 처음에는 빈 목록이고, 상품 2개를 등록하면 두 상품의 정보를 확인할 수 있습니다.
재고 변경 ID로 상품을 찾아 새 재고 수량으로 교체합니다. 10 → 7로 바꾸면 조회 결과도 7이어야 합니다.
상품 간 독립성 한 상품의 재고를 바꿔도 다른 상품의 정보는 그대로 유지됩니다.

데이터는 프로그램이 실행되는 동안만 유지하면 됩니다. 목록 정렬은 오늘의 필수 조건이 아닙니다. 처음에는 서로 다른 ID, 정상 이름, 0 이상의 가격·재고로 정상 흐름부터 만듭니다.

진행 순서

  1. 객체 설계: 상품 한 개의 상태와 상품 여러 개를 관리하는 책임을 어떻게 나눌지 적습니다. 어떤 객체가 재고 변경을 책임질지도 정합니다.
  2. 컬렉션 선택: List와 Map 중 하나를 고르고, 목록 조회와 ID 검색에 어떤 차이가 있는지 한두 문장으로 적습니다.
  3. 직접 구현: 등록 → 목록 조회 → 재고 변경 순서로 만듭니다. 처음에는 Main에 직접 입력한 예제 데이터로 호출해도 됩니다.
  4. 테스트 작성: ProductInventoryTest의 테스트를 하나씩 채웁니다. fail(...)을 실제 검증문으로 바꾸고 해당 테스트의 @Disabled를 제거합니다. 각 테스트는 새 객체와 데이터를 사용합니다.
  5. 디버깅: 직접 만든 재고 변경 메서드에 중단점을 둡니다. 테스트를 Debug로 실행해 ID, 컬렉션 내용, 변경 전후 재고를 확인하고 한 줄씩 진행합니다.
  6. 경계 조건: 정상 흐름이 끝나면 중복 ID, 없는 ID로 재고 변경, 음수 재고를 차례로 다룹니다. 실패 시 기존 데이터가 유지되는지도 검증합니다. 별도 예외 계층을 만드는 일은 뒤로 미뤄도 됩니다.

테스트 이름만 통과시키기 위해 fail(...)을 지우지는 마세요. 준비한 값과 실제 결과를 비교하는 검증이 있어야 합니다. 처음의 성공 결과는 실행 환경 확인입니다. 상품 테스트 4개가 모두 활성화되어 통과하면 기본 기능을 검증한 것입니다.

완료 체크

  • 상품 데이터와 상품 관리 책임을 설명할 수 있습니다.
  • 컬렉션 선택 이유를 설명할 수 있습니다.
  • 등록한 상품 목록을 확인하고 특정 상품의 재고를 바꿀 수 있습니다.
  • 상품 테스트 4개가 활성화되어 통과합니다.
  • 디버거로 재고가 변경되는 순간을 확인했습니다.
  • 경계 조건 하나 이상을 추가로 검증했습니다.
